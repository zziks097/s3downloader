# S3 Downloader

CLI-утилита для параллельного скачивания всех объектов из S3 / S3-compatible bucket.

## Возможности

- YAML-конфигурация endpoint, credentials, bucket и локального каталога.
- Параллельное скачивание (`download.workers`).
- Постраничный обход bucket через ListObjectsV2.
- Checkpoint в JSON после каждого успешно скачанного объекта.
- Возобновление: при повторном запуске объекты с совпадающими ETag/размером и существующим локальным файлом пропускаются.
- Временный `.part` файл, проверка размера и checksum до атомарного переименования.
- Retry с увеличивающейся задержкой.
- Остановка через Ctrl+C / SIGTERM.
- Лог в файл и stdout.

## Запуск

Требуется Go 1.22 или новее.

```bash
cp config.yaml.example config.yaml
# заполнить config.yaml
go mod tidy
go build -o s3downloader .
./s3downloader -config config.yaml
```

В репозитории пример конфигурации находится в `config.yaml`.

## Контрольные суммы

При скачивании приложение запрашивает checksum через `ChecksumMode=ENABLED` и сравнивает доступные S3 checksum (SHA256, SHA1, CRC32, CRC32C) с локально вычисленными значениями. Если сервер не возвращает checksum, приложение использует ETag как MD5 только для ETag без суффикса multipart (`-N`). Multipart ETag не является MD5 и не используется для такой проверки.

Локальный SHA256 вычисляется для каждого объекта и сохраняется в state-файле. Если сервер не предоставляет ни checksum, ни применимый MD5 ETag, строгого сравнения с удалённой контрольной суммой нет: приложение может подтвердить только размер и сохранить локальный SHA256.

## Возобновление

Файл `s3downloader-state.json` содержит успешные объекты. При следующем запуске bucket перечисляется заново, а объект пропускается, если:
- ключ присутствует в state;
- ETag и размер совпадают с текущими метаданными S3;
- локальный файл существует и имеет ожидаемый размер.

Если объект изменился (ETag или размер), он скачивается заново. Для защиты от повреждения локального файла после завершения скачивания рекомендуется не изменять файлы назначения вручную.

## Права доступа

Для скачивания нужны как минимум `s3:ListBucket` на bucket и `s3:GetObject` на объекты. Для некоторых AWS buckets с SSE-KMS также может понадобиться `kms:Decrypt`.

## Важные замечания

- Для S3-compatible сервисов часто требуется `force_path_style: true`; для AWS S3 обычно можно оставить `false`.
- Учетные данные хранятся в YAML открытым текстом. Ограничьте права на файл (`chmod 600 config.yaml`) или используйте секрет-хранилище перед эксплуатацией.
- State-файл рассчитан на один экземпляр приложения. Не запускайте одновременно несколько копий с одним state-файлом и каталогом назначения.
- Если требуется максимально строгая проверка, включите сохранение checksum при загрузке объектов на стороне S3. Без удалённой checksum нельзя математически сравнить локальный файл с оригиналом.
